# Phase 5: `@clawforge/web` — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans.

**Goal:** Ship `apps/web` — the clawforge.dev Astro site. MVP pages: landing, browse, entry detail, docs. Reads the registry index directly at build time (no runtime fetching). Deploys to Cloudflare Pages.

**Architecture:** Astro 5 SSG. At build time, read `dist/registry.json` produced by `@clawforge/build-index` (fixture for dev, real CDN output for prod). Generate static pages per entry. Use Tailwind 4 for styling, hand-rolled components (shadcn copy-paste snippets deferred to post-MVP). Pagefind for static search.

**Spec reference:** §6 (web UI), §3 (repo structure places this in `apps/web/`).

## MVP scope (4 page types, not 10)

| Path | Purpose |
|---|---|
| `/` | Landing: hero, install command, featured 6, stats |
| `/browse` | All entries grid with client-side kind/tag filter |
| `/[kind]/[slug]` | Entry detail (most SEO value) |
| `/docs` | Single MDX page (getting-started) |

Deferred to post-MVP: `/submit`, `/stats`, `/author/*`, `/tag/*`, `/category/*`, OG image generation, MeiliSearch widget, sitemap auto-gen (already produced by build-index at CDN root).

### Task 2: Data loader

File: `src/lib/registry.ts`.

Read `registry.json` from a path set via environment variable `CLAWFORGE_REGISTRY_DIR` (default `../../packages/build-index/tests/fixtures/dist` for dev — we run build-index on the fixture at dev-server start). Parse with `@clawforge/schema` `RegistryIndexSchema`. Expose:

- `getIndex(): RegistryIndex`
- `getEntryByKindSlug(kind, slug): IndexEntry | null`
- `getFeatured(limit = 6): IndexEntry[]`

Pure synchronous readers (Astro build-time, no async needed for local FS).

**Commit:** `feat(web): add registry data loader`

## Exit criteria

- `astro build` produces static HTML with no errors.
- Browsing the `dist/` output locally shows: landing, browse (with > 0 entries), at least one detail page, docs.
- Dark mode toggle persists.
- Biome clean across repo.
- Tag `phase-5-web-complete` on last commit.

## Non-goals (explicit)

- Perfect Lighthouse scores (we optimise in P9 launch prep).
- OG image generation (post-MVP).
- MeiliSearch widget (Pagefind or client-side substring is fine).
- Submit / author / tag / category pages (post-MVP).
- Complex design-system refinement (hand-rolled Tailwind is fine).
